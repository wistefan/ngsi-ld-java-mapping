# Implementation Plan: Update ngsi-ld-java-mapping to Micronaut 5.1.3

## Overview
Move the library from Micronaut 4.6.5/4.10.11 (Jackson 2.18) to the Micronaut platform 5.1.3. That platform manages micronaut-core 5.1.13, Jackson **3.1.5** (`tools.jackson.*`), jackson-annotations 2.21, reactor 3.8.x and Netty 4.2. In Micronaut 5, `micronaut-jackson-databind` is built on Jackson 3 and immutable mappers: `ObjectMapperFactory` builds a `JsonMapper` from a `tools.jackson.core.json.JsonFactory` bean plus `JacksonModule`, `ValueSerializer` and `ValueDeserializer` beans. Every Jackson-dependent class in the library therefore has to be migrated. Public behaviour (mapping results, escape cleaning, AdditionalProperty polymorphism, GeoQuery handling) must not change.

Facts verified on Maven Central and by inspecting the 5.1.13 jars:
- `io.micronaut.core.annotation.{Nullable,NonNull,Introspected}`, `io.micronaut.core.serialize.ObjectSerializer`, `io.micronaut.jackson.JacksonConfiguration`, `@ConfigurationProperties` and `@Client` still exist in Micronaut 5.
- The generated client (kokuwa codegen 3.2.2) only uses Jackson **annotations** (`com.fasterxml.jackson.annotation`, unchanged in Jackson 3), Micronaut http/core annotations, `jakarta.annotation.Generated` and `reactor.core.publisher.Mono`. It should compile unchanged.
- `EntityVOMapper`'s constructor currently **mutates the injected, shared ObjectMapper**: it adds `AdditionalPropertyMixin` and a `GeoQueryDeserializer` module. The HTTP client therefore deserializes `AdditionalPropertyVO`/`GeoQueryVO` with these customisations. Jackson 3 mappers are immutable, so these customisations must become a module bean that Micronaut's factory registers.

## Steps

### Step 1: Decouple Jackson customisations from mapper mutation (still on Micronaut 4 / Jackson 2)
This is a refactor that keeps the build green and makes Step 2 a mechanical API port.
- Add `src/main/java/io/github/wistefan/mapping/NgsiLdMappingModule.java`: a `@Singleton` `SimpleModule` subclass that sets the mixin `AdditionalPropertyVO -> AdditionalPropertyMixin` (`setMixInAnnotation`) and adds `GeoQueryDeserializer` for `GeoQueryVO`. Micronaut 4's `ObjectMapperFactory` already registers all `Module` beans, so the global mapper gets exactly what the `EntityVOMapper` constructor used to add.
- `EntityVOMapper`: remove `addMixIn`, `registerModule` and `findAndRegisterModules` from the constructor so it no longer mutates the injected mapper. On the DI path nothing is lost: Micronaut's `ObjectMapperFactory` registers the `NgsiLdMappingModule` bean and module-scans (`jackson.module-scan`, default true), which picks up `JavaTimeModule`. Consumers who construct `EntityVOMapper` with their own mapper now have to register `NgsiLdMappingModule` and java.time support themselves. Record this in the PR description so it ends up in the 2.0.0 release notes (see Step 3).
- `EntityVOMapper` and `JavaObjectMapper`: replace `javax.inject.Singleton` with `jakarta.inject.Singleton`, which is the only form Micronaut 4/5 processes. Drop the `javax.inject` dependency and its `version.javax.inject` property from `pom.xml` if nothing else uses it.
- Tests: `EntityVOMapperTest` (and any other test that passes a hand-built mapper to `EntityVOMapper`) must register `new NgsiLdMappingModule()` on its `ObjectMapper` **and** call `findAndRegisterModules()` (or register `JavaTimeModule`), so the tests keep exercising the same configuration. The constructor's `findAndRegisterModules()` currently provides JSR-310 support. Without it, `mapWithWellKnown` (`Instant.MAX`) fails with "Java 8 date/time type not supported".
- Add `src/test/java/io/github/wistefan/mapping/MappingContextTest.java`. It starts `ApplicationContext.run(Map.of("micronaut.http.services.ngsi.url", "http://localhost:1026"))` with a dummy URL constant, so that resolving `EntityVOMapper` → `EntitiesRepository` → the generated `@Client(id = "ngsi")` API fails only on Jackson wiring and not on missing client config. No `micronaut-test` is needed; context and jackson-databind are already on the provided/test classpath. Close the context in `@AfterAll`. It asserts:
  1. `EntityVOMapper`, `JavaObjectMapper`, `EntityVOSerializer` and `CacheSerdeableObjectMapper` are resolvable beans.
  2. The context `ObjectMapper` uses `EscapeCleaningJsonFactory`. Deserializing JSON with an escaped reserved key yields the unescaped name, both as a tree/map key **and** when it is bound to a bean property (e.g. a VO whose `@JsonProperty("@context")` field is read from `"tmfEscaped-@context"`; pick a key that `ReservedWordHandler.canUnescapeDuringParsing` allows). The bean case is the one Jackson 3 breaks (see `EscapeCleaningParser` in Step 2).
  3. The context `ObjectMapper` deserializes a `GeoQueryVO` via `GeoQueryDeserializer` and applies the `AdditionalPropertyMixin`. Reuse a JSON fixture from `EntityVOMapperTest`.
  Use `@ParameterizedTest` where cases form a table. This test guards the DI wiring through the framework switch in Step 2.
- Implementation notes (found while implementing):
  - `EntitiesRepository` is a plain interface with no implementation in the library; consumers provide one. `MappingContextTest` therefore declares a nested `@Singleton TestEntitiesRepository`. The dummy ngsi URL is kept but is not strictly needed.
  - The pom mixed `micronaut-core`/`micronaut-jackson-databind` 4.6.5 with `micronaut-http-client` 4.10.11, which pulls `micronaut-context`/`micronaut-inject` 4.10.11. A real `ApplicationContext` fails with `NoClassDefFoundError: io/micronaut/core/util/AnsiColour`. Step 1 aligns `micronaut.version`, `micronaut-core` and `micronaut-jackson-databind` to 4.10.11.
- Acceptance: `mvn clean verify` is green on Micronaut 4. No other behaviour change.

### Step 2: Switch to the Micronaut 5.1.3 platform and migrate to Jackson 3
This step must be atomic: the pom switch breaks compilation until the code is ported.

**Java 25 (added during implementation):** the Micronaut 5.1.13 jars are compiled to Java 25 bytecode (class major version 69), so `jdk.version`/`release.version` move to 25 and the `setup-java` steps in `.github/workflows/{test,check,release}` use JDK 25. Lombok moves to 1.18.42 and jacoco to 0.8.14, since older versions can't handle Java 25.

**pom.xml**
- Add `<micronaut.platform.version>5.1.3</micronaut.platform.version>` and import `io.micronaut.platform:micronaut-platform:${micronaut.platform.version}` (`type=pom`, `scope=import`) in a new `<dependencyManagement>`. Remove `micronaut.version`, `version.io.micronaut.micronaut-core`, `version.io.micronaut.micronaut-http-client` and `version.io.micronaut.micronaut-jackson-databind`, then drop the `<version>` tags of the managed `io.micronaut:*` dependencies. Keep them `provided`.
- Replace `com.fasterxml.jackson.core:jackson-databind` with `tools.jackson.core:jackson-databind`, version from the BOM. Remove `jackson-datatype-jsr310`, because java.time support is built into Jackson 3 databind. Add `com.fasterxml.jackson.core:jackson-annotations`, version from the BOM, explicitly, since the code uses the annotations directly. Delete the now-unused Jackson version properties.
- Let the BOM manage `reactor-core` and `slf4j-api` and remove their version properties. If the BOM doesn't manage reactor-core, pin it to the version `micronaut-http-client` 5.1.13 depends on (3.8.7).
- `micronaut-inject-java` annotation processor: bump `maven-compiler-plugin` to ≥ 3.12 and set `<annotationProcessorPathsUseDepMgmt>true</annotationProcessorPathsUseDepMgmt>` so its version comes from the BOM. Apply this to both the main and the `test-compile` execution. If that isn't possible, add a named property `micronaut.core.version` = 5.1.13 with a comment tying it to the platform version.
- Keep `openapi-generator` 6.5.0 and kokuwa codegen 3.2.2 if the generated sources compile. Bump the generator only if they don't, and record the reason in the PR.

**Main code (`src/main/java/io/github/wistefan/mapping/`)**: `com.fasterxml.jackson.{core,databind}` → `tools.jackson.{core,databind}`. Keep `com.fasterxml.jackson.annotation`. `JsonProcessingException`/`IOException` from Jackson calls → `tools.jackson.core.JacksonException`, which is unchecked.
- `EscapeCleaningJsonFactory`: extend `tools.jackson.core.json.JsonFactory`. `ObjectCodec`/`setCodec` no longer exist. Override the protected `_createParser(ObjectReadContext, IOContext, …)` variants (InputStream, Reader, char[], byte[], DataInput) to wrap `super._createParser(...)` in `EscapeCleaningParser`. Keep `@Primary @Singleton`, which is the bean `ObjectMapperFactory.jsonMapperBuilder(JacksonConfiguration, JsonFactory)` consumes.
  - Decision: honour `jackson.json-factory-features`. Today the `@Primary` factory silently drops them, and Micronaut 5.1.13's own `jsonFactory(JacksonConfiguration)` bean applies them. Add an `@Inject` constructor taking `JacksonConfiguration` that applies its factory feature settings to `JsonFactory.builder()` and passes the builder to the protected `JsonFactory(JsonFactoryBuilder)` super-constructor. Use `javap` on micronaut-jackson-core 5.1.13 to find the accessor name, and copy what `ObjectMapperFactory.jsonFactory(...)` does. Keep a no-arg constructor (default features) for the hand-built test mappers.
  - Override `copy()` to return a new `EscapeCleaningJsonFactory` with the same settings. Check with `javap` whether `JsonMapper.Builder`/`MapperBuilder` call `copy()`, `snapshot()` or `rebuild()` on the factory. If they do, override those methods too so the subclass survives. `rebuild()` returns a plain `JsonFactoryBuilder`, so if the mapper path uses it, override it to throw `UnsupportedOperationException` rather than silently losing escape cleaning. Assert in the tests that `mapper.tokenStreamFactory()` is an `EscapeCleaningJsonFactory`.
- `EscapeCleaningParser`: extend `tools.jackson.core.util.JsonParserDelegate`. Remove `getCurrentName()`, which no longer exists, and keep `currentName()`. **Mandatory:** in jackson-core 3.1.5, `JsonParserDelegate.nextName()`, `nextNameMatch(PropertyNameMatcher)` and `currentNameMatch(PropertyNameMatcher)` forward straight to the delegate. `BeanDeserializer` (`_vanillaDeserialize`, `deserializeFromObject`) matches properties via `nextNameMatch`/`currentNameMatch`, not `currentName()`. Without overrides, escaped keys stop binding to bean properties and fall through to the any-setter/unknown-property path. Override all of these to go through `cleanName(...)`:
  - `nextName()`: advance with `nextToken()`. Return `currentName()` if the token is `PROPERTY_NAME`, otherwise `null`.
  - `nextNameMatch(m)`: advance with `nextToken()`. Return `m.matchName(currentName())` for `PROPERTY_NAME`, `PropertyNameMatcher.MATCH_END_OBJECT` for `END_OBJECT`, and `PropertyNameMatcher.MATCH_ODD_TOKEN` otherwise. Check the constant names with `javap`.
  - `currentNameMatch(m)`: the same mapping for the current token, without advancing.
  - `getString()` (and `getText()`, if it still exists): return `currentName()` while the current token is `PROPERTY_NAME`, because some deserializers read names via the text accessor.
  - Add a parameterized `EscapeCleaningParserTest` case table (tree key, `Map` key, bean property) next to the bean-property assertion in `MappingContextTest`.
- `CacheSerdeableObjectMapper`: Jackson 3 `ObjectMapper` has no `addMixIn`/`findAndRegisterModules`. Make it extend `tools.jackson.databind.json.JsonMapper` and call `super(JsonMapper.builder().addMixIn(...)x3.findAndAddModules())`, keeping the no-arg constructor and its `@Singleton @Bean`.
- `NgsiLdMappingModule`: `tools.jackson.databind.module.SimpleModule`. It is picked up as a `JacksonModule` bean.
- `GeoQueryDeserializer`: `tools.jackson.databind.deser.std.StdDeserializer`.
- `AdditionalPropertyTypeResolver`: `buildTypeDeserializer(DeserializationContext ctxt, JavaType, Collection<NamedType>)`. Use `TypeNameIdResolver.construct(ctxt.getConfig(), ...)` and `defineDefaultImpl(ctxt, baseType)`, checking that method's Jackson 3 signature.
- `AdditionalPropertyDeserializer`: port to the Jackson 3 `AsArrayTypeDeserializer`/`AsPropertyTypeDeserializer` constructors. `AsPropertyTypeDeserializer` now takes `(JavaType, TypeIdResolver, String, boolean, JavaType, JsonTypeInfo.As, boolean)`. `new TokenBuffer(p, ctxt)` becomes `TokenBuffer.forBuffering(p, ctxt)`. Use `asParser(ctxt)`/`asParserOnFirstToken(ctxt)`. Override the renamed `_deserialize...` hooks; check them with `javap` against jackson-databind 3.1.5.
- `AdditionalPropertyMixin`: `@JsonTypeResolver` → `tools.jackson.databind.annotation.JsonTypeResolver`.
- `EntityVOSerializer`: `JacksonConfiguration.constructType(Argument, TypeFactory)` against the Jackson 3 `TypeFactory`. Use `objectMapper.getTypeFactory()` or `typeFactory()`, whichever exists in 3.1.5. Map `JacksonException` to `SerializationException`.
- `EntityVOMapper`/`JavaObjectMapper`: swap imports (`TypeReference` → `tools.jackson.core.type.TypeReference`) and replace `JsonProcessingException` catch blocks with `JacksonException`. Keep the public method signatures. Any method that declared `throws JsonProcessingException` should drop it or declare `JacksonException`.

**Tests (`src/test/java/...`)**: port the imports the same way. Hand-built mappers become `JsonMapper.builder(new EscapeCleaningJsonFactory()).addModule(new NgsiLdMappingModule()).build()` (or `new JsonMapper()`). `BeanDeserializerModifier` → `ValueDeserializerModifier`, `SettableBeanProperty`/`BeanDeserializerBuilder` → `tools.jackson.databind.deser.*`. `SerializationFeature`/`JsonInclude` settings move to the builder (`changeDefaultPropertyInclusion`, `.disable(...)`), and so does `objectMapper.configure(...)`. Test expectations must not change. If a Jackson 3 default changes output (e.g. `WRITE_DATES_AS_TIMESTAMPS` now defaults to false, or property ordering is now alphabetic via `SORT_PROPERTIES_ALPHABETICALLY`), restore the 2.x behaviour in the mapper configuration and don't edit the expected values.

- Acceptance: no `com.fasterxml.jackson.core`/`com.fasterxml.jackson.databind` imports remain (`grep -r` is empty). `mvn dependency:tree` shows micronaut 5.1.13, `tools.jackson` 3.1.5 and no Jackson 2 databind. `mvn clean verify` passes. The Step 1 cases in `MappingContextTest` stay unchanged, with one new case added: a configured `jackson.json-factory-features` entry is reflected on the context mapper's factory.

### Step 3: Documentation and release metadata
- `README.md`: add a short "Requirements" note: Micronaut 5.x (platform 5.1.3+), Jackson 3 (`tools.jackson`), Java 25. Also note that consumers on Micronaut 4/Jackson 2 must stay on 1.x.
- `AGENTS.md`: update the Tech Stack (Micronaut platform 5.1.3, Jackson 3, BOM import, Java 25 for build and CI) and conventions (`tools.jackson` packages, unchecked `JacksonException`, customisations live in `NgsiLdMappingModule`, no mapper mutation).
- `pom.xml`: set `<version>` to `2.0.0`. The public API now exposes Jackson 3 types (`CacheSerdeableObjectMapper`, `EscapeCleaningJsonFactory`), which is a breaking change. The release workflow derives the version from the PR semver label, so the PR to `main` must carry the **major** label. Say so in the PR description. The PR description (release notes) must also list these migration points: Jackson 3 types in the public API; `EntityVOMapper` no longer mutates the injected mapper, so a hand-built mapper needs `NgsiLdMappingModule` (plus java.time support on 1.x-style setups); `jackson.json-factory-features` is now honoured. The generated `org.fiware.ngsi.model.*VO` classes are no longer `@Introspected` (codegen `introspected=false`): Micronaut 5's introspection processor fails on `RelationshipVO`'s private `_object` field, which no getter matches. Consumers that need `BeanIntrospection` of the VOs must declare `@Introspected(classes = ...)` for them in their own code. That works for every VO except `RelationshipVO`. Java 25 is the new baseline, because the Micronaut 5.1.13 jars are class version 69. Jackson 3 changed defaults, and Micronaut 5 does not restore them on the context `ObjectMapper`. The library does not mutate that mapper, so consumers who need the 1.x behaviour set `jackson.mapper-features.sort-properties-alphabetically: false` (bean properties otherwise serialize alphabetically), `jackson.deserialization-features.fail-on-null-for-primitives: false` (`readValue` of a JSON `null` into a primitive otherwise throws; `EntityVOMapper.convertValue` is not affected because Micronaut's default `NON_EMPTY` inclusion drops null map entries first) and `jackson.date-time-features.write-dates-as-timestamps: true` (java.time values otherwise serialize as ISO strings). `CacheSerdeableObjectMapper` keeps these three Jackson 2 defaults itself. `MappingContextTest.jackson2DefaultsRequireConfiguration` covers the keys.
- Acceptance: `mvn clean verify` green. The docs match the pom.
